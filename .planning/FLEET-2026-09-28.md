1. **The fact, in the site's own words** — "a meeting is done", not "the checked flag".
2. **How many places decide it now, and how many after.** "Three before, one after."
3. **The name of the check that goes red if a second place ever appears** — a script under
   `scripts/qa/` that you write, that exits non-zero, and that the coordinator will run.

### THE CONTRACT between B and C — rendered text that an editor can change

Every piece of text that the site draws from data (not written into the HTML) carries:

```html
<span data-field="series/secular/sessions.1.title">Lessons 1–6</span>
```

`data-field="<collection>/<itemKey>/<fieldPath>"`:
- `<collection>` is a document under `content/` (the ones `js/content.js` already serves:
  testimonials, videos, events, publications, people, stats — plus the new ones below).
- `<itemKey>` is the item's `id`, else its `key`, else its index in the array.
- `<fieldPath>` is a dot path inside that item (`quote`, `role`, `sessions.1.before.detail`).
C builds the one editor that finds `[data-field]`, edits it in place in the same "Edit page text" bar,
and saves it into that collection through `saveCollection` (so it lands in History and can be restored).
B makes the group series a collection, `series`, whose defaults come from `SERIES` in `js/data.js`
(B adds `series` to `DEFAULTS` in `js/content.js` — one line; C adds its functions elsewhere in that
file), and B emits `data-field` on every series text it draws. **C must also work for elements drawn
AFTER the bar mounts** (the series, testimonials and My Path all render late).
