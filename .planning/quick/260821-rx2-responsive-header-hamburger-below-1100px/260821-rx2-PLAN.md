<architecture_note>
ONE header path (CLAUDE.md rule 8 — no forks). The design that achieves D-02 without duplicating
any DOM node and without touching auth.js:

- buildHeader gains exactly one new element: the `.nav-toggle` button (DOM-last in `.site-head`).
- Below 1100px, `.site-auth { display: contents }` promotes the auth slot's children to direct
  flex items of `.site-head`. Flex `order` then arranges the top row (brand 0, `.site-auth .btn`
  1, `.nav-toggle` 2) and the panel rows (`.site-nav` order 10, `.site-auth .signin` order 11,
  both `flex-basis: 100%` so `.site-head`'s existing `flex-wrap: wrap` drops them to full-width
  rows below). Panel rows are hidden unless `.site-head[data-menu-open]`.
- This works unmodified for BOTH mountAuth states: signed-out (`.signin` -> panel, `.btn--outline`
  -> row) and signed-in (single `.btn--quiet` -> row, panel is nav only). One render path, CSS
  decides presentation.
- `appendCustomNav()` appends editor pages into `.site-nav`, so they appear in the panel
  automatically — no extra handling.
- All new CSS lives in a `@media (max-width: 1099.98px)` block plus a base
  `.nav-toggle { display: none }` rule, so >=1100px cannot change (D-03 is structural, and the
  verify gate proves it: zero deleted lines in the css diff).
</architecture_note>
